PharmaScan 用药周期

PharmaScan · 第一至第三阶段

从医生到患者的一个完整用药周期

从开出新处方到疗程结束的每一步：每个人点击什么、系统中哪一部分在工作，以及对应的 PharmaScan API 调用。示例患者服用二甲双胍（metformin）500 mg、氨氯地平（amlodipine）5 mg 和立普妥（Lipitor，即阿托伐他汀）10 mg；之后医生加开克拉霉素（clarithromycin）。

已上线（API 中可用） 已规划（features.md） 尚未开发 网站团队 第一阶段队友 原型中为模拟

API 地址：https://davidpansx-pharmascan-api.hf.space。网站直接从浏览器调用它；API 不保存任何数据。

阶段 A · 每张处方一次

医生开处方，我们的系统做准备

在患者打开任何页面之前，在后台完成。不需要患者拍任何照片。

1

医生 · 诊所系统

医生开出处方

  • 二甲双胍 500 mg，08:00 和 20:00 各 1 片
  • 氨氯地平 5 mg，08:00 1 片
  • 立普妥 10 mg，21:00 1 片

记录里最好也带上所配药品的产品代码（NDC）：它能准确告诉我们药房发的是哪一种药片，因为每个厂家的药片外观都不一样。

模拟

不调用 PharmaScan。真正接入国家健康记录需要其管理方批准；原型使用字段相同的模拟数据源。

2

健康记录数据源 → 我们的后端

处方存入我们的数据库

以内部患者 ID 保存，药物 ID 为 m1、m2、m3，并附服药时间和疗程长度。NRIC 只留在登录环节，绝不出现在 PharmaScan 调用中。

网站团队

后端和数据库工作。不调用 PharmaScan。

3

我们的后端 → PharmaScan API · 第三阶段

检查整份药单的相互作用和重复用药

每次药单变更都会发送。对这份药单，API 返回一条琥珀色警报（氨氯地平与立普妥，中度：向患者语音朗读）和两条灰色警报（有相互作用记录，但严重程度未分级：只显示）。如果出现红色警报，会在患者看到药单之前先发给药剂师或医生。

POST/v1/safety/medications已上线
{"medications": [
  {"id": "m1", "name": "Metformin 500 mg"},
  {"id": "m2", "name": "Amlodipine 5 mg"},
  {"id": "m3", "name": "Lipitor 10 mg"}]}
回复 
{"alerts": [
  {"type": "interaction", "severity": "moderate", "colour": "amber",
   "medication_ids": ["m2", "m3"],
   "message": "Amlodipine 5 mg and Lipitor 10 mg have a moderate
               interaction. Check with your pharmacist."},
  {"severity": "ungraded", "colour": "grey", ...},   // m1 + m2
  {"severity": "ungraded", "colour": "grey", ...}],  // m1 + m3
 "all_identified": true}

5

我们的后端 → PharmaScan API · 第二阶段

用目录为患者建立个人图库

每个产品的参考图片转换成 256 个数字的嵌入向量，连同模型版本以及第 4 步得到的药片印记，一起保存为该药物的个人图库。模型的个性化就来自这里：它把每张药片照片与这个图库比较，所以不需要用患者的药物来训练。

GET/v1/pills/{pill_id}/embeddings尚未开发
// 建议的接口；后端保存为
{"medication_id": "m1", "name": "Metformin 500 mg", "imprint": "93;7267",
 "embeddings": [[...256 个数字...], ...],
 "model_version": "stage2_run4@2026-10-09"}

用目录建立的图库准确率还没有测量：我们 76% 正确、0% 错误的数字，用的是日常照片建立的图库。

7

患者 · 网站 → 第一阶段 → PharmaScan API

可选，第一次服用时：为这种药添加照片

用患者自己的手机拍 3 到 5 张，正反两面。这些照片比目录图片匹配得更好（同一部相机、同样的光线），也能覆盖目录里没有的药物。

阶段 C · 每一次服药，一直重复到疗程结束

服药前先检查这一剂药

示例：08:00 这一剂应该是一片二甲双胍和一片氨氯地平。

9

我们的后端 → 患者

08:00 提醒；患者点击 检查我 8:00 的药

患者把药片分开放在素色平面上，拍一张照片。

网站团队

提醒（推送、短信或电子邮件）和拍照页面。不调用 PharmaScan。

10

网站 → 第一阶段检测器

找出照片中的每一颗药片

检测器为每颗药片返回一个框，单位是照片像素。它在哪里运行（浏览器还是服务器），还需要与第一阶段队友商定。

第一阶段队友
[[412, 300, 655, 540], [720, 310, 930, 520], [180, 620, 390, 820]]

在检测器完成之前，/v1/scan 可以在素色背景上自己找出药片。

11

网站 → PharmaScan API · 第二和第三阶段一次完成

识别每颗药片并检查剂量

网站发送照片、框、患者的个人图库和这一剂的服药安排。API 还会读取每颗药片上的印记，并与个人图库中的印记核对：可以确认匹配、在两种外观相似的药之间做出区分，或者当印记属于患者的另一种药时，请患者重新拍照。大约 2 到 3 秒。

           boxes    = [[412,300,655,540], ...]
           gallery  = [{"medication_id":"m1","name":"Metformin 500 mg",
                        "embeddings":[[...],...]}, ...]
           schedule = [{"medication_id":"m1","count":1},
                       {"medication_id":"m2","count":1}]
           model_version = stage2_run4@2026-10-09
回复 
{"pills": [
  {"box": [...], "decision": "match", "medication_id": "m1",
   "message": "This is your Metformin 500 mg.", "imprint_check": "confirmed"},
  {"box": [...], "decision": "match", "medication_id": "m2", ...},
  {"box": [...], "decision": "unknown", "medication_id": null,
   "message": "This pill isn't one of your medicines. Set it aside. Check with your pharmacist."}],

患者 · 网站

在照片上查看结果

  • match：显示药名，绿色。
  • unknown：「不是您的药，请放到一边」。
  • ambiguous：「请把药片翻过来再拍一次」：回到第 9 步。

警报按颜色处理：红色和琥珀色会语音朗读，红色还会通知照护者。

点击 我已经服药

网站团队

服药记录和通知。API 上的可选功能：患者询问时，用 GET /v1/safety/label?rxcui=… 查看官方警告（已上线）；征得同意后，用 POST /v1/feedback 分享照片（已开发，但处于关闭状态；F5 仍只是在考虑中）。

16

我们的后端

一个疗程结束

第 7 天之后，克拉霉素从个人图库和服药安排中移除。如果之后再拍到这种药，会被标记为不是患者的药。后端向医生或药剂师发送服药依从性摘要：检查过的剂次、漏服的剂次，以及发现的多余药片。

网站团队

更新个人图库和服药安排，以及摘要报告。不调用 PharmaScan。

17

我们的后端 → PharmaScan API

当我们发布新模型时

不同模型版本的嵌入向量不能互相比较。如果 /v1/scan 返回 409，后端会为保存的登记照片重新生成嵌入向量，并刷新目录嵌入向量，然后重试。

POST/v1/scan已上线
409 → {"detail": "gallery embedded with model stage2_run4@2026-10-09,
        but stage2_run5@... is served"}
POST/v1/embed已上线
// 每张保存的登记照片调用一次，然后重试扫描

然后带着新药单回到阶段 A：下一个周期开始。

总结

谁负责做什么

PharmaScan API 已上线

  • /v1/safety/medications（第 3、15 步）
  • /v1/pills/search 和图片（第 4、6 步）
  • /v1/embed（第 7、17 步）
  • /v1/scan（第 11 步）
  • /v1/identify（第 13 步），并从照片读取印记
  • /v1/read-label（第 8 步）
  • /v1/safety/label、/v1/match、/v1/safety/dose

API 中还需开发

  • 尚未开发 用于个人图库的目录嵌入向量（第 5 步），以及测量这种图库的准确率
  • F9 书面的嵌入向量规范和 /v1/verify
  • 在真实手机照片上测试药盒和标签识别：目前只用打印的示例测试过

网站团队 网站

  • Singpass 登录（原型中为模拟）
  • 从数据源接收处方（模拟）
  • 数据库：药单、个人图库、服药安排、服药记录
  • 提醒、结果页面、照护者警报、服药依从性摘要

第一阶段队友 检测器

  • 为每颗药片给出一个框，格式为 [x0, y0, x1, y1]，单位是照片像素（第 10 步）
  • 商定在哪里运行：浏览器还是服务器

谁保存哪些数据

  • 我们的后端保存身份（Singpass）、处方、个人图库、服药安排和服药记录。
  • PharmaScan API 不保存任何数据。它只看到药片照片、匿名的药物 ID 和药名，回答后即丢弃。
  • 新加坡 PDPC 的规定限制收集 NRIC 号码：请通过 Singpass 登录，并且不要把 NRIC 放进其他任何数据表。
