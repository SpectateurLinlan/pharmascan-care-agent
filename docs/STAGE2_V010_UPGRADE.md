# Stage2 0.10.0 integration and acceptance

Date: 2026-10-15, Asia/Singapore. This document records this upgrade, separately from earlier v0.8/v0.9 results.

## Contract and service

The supplied [0.10.0 snapshot](external/pharmascan-api-openapi-0.10.0.json) is the current injected runtime contract. Retained 0.8.0/0.4.0 snapshots are unchanged. There is no retained official 0.9.0 snapshot in this checkout; the former 0.9 compatibility gate is not a substitute for a schema diff.

`python scripts/stage2_contract_diff.py` creates the complete [JSON-pointer diff](external/pharmascan-api-0.8.0-to-0.10.0.diff.json): 40 changed nodes. New paths are only `/v1/check-input` and `/v1/search-by-embedding`. Safety and feedback paths already existed in 0.8.0. Existing multipart `medications` remains an optional JSON **string**, not a JSON request body. Existing embed `read_imprint` and match `query_reads` are reused, not invented as new request fields.

Changed response evidence includes `Instructions`, `Dose`, `Quantity`, `Caution`, `DocumentFields.instructions/indication/cautions`, candidate `release/release_printed`, response `label_kind/dispensed_by`, model-info required `similarity/error_rates`, look-alike strength caveats, optional reference-set identifiers and text-reader metadata. `Instructions.text/line` and `Dose.amount` are required; other dose/frequency/food/duration/max components may be absent/null. `as_needed` defaults false and is not evidence of a fixed schedule. The diff contains no newly deprecated field. Extra provider properties are projected away at the adapter.

REAL LIVE metadata probes: `/health`, `/v1/model-info`, `/v1/tools` returned JSON HTTP200. API0.10.0 is separate from model `stage2_run4@2026-10-09`, space `pill-crop:stage2_run4@2026-10-09:w1.55`, preprocess `crop-contract-1:window-1.55:crop-384:input-224`, dimension256, normalized=true. Provider threshold0.8948970437049866 and margin0.115 are retained with calibration provenance, not application guarantees. Existing references are compared only when model/space/preprocess/dimension/normalization match; no automatic invalidation or re-embedding follows merely from API version.

## Source mapping and reconciliation

`PharmaScanLabelProvider` validates the complete supplied schema before mapping to public typed DTOs. `Printed.value/line`, instruction `text/line`, parsed dose/range/unit/count/interval/PRN/time wording/food/duration/max, dispensed quantity, indication, cautions, source, OCR model and dispensing origin are preserved as unreviewed evidence. Product strength/release/ingredients/codes remain separate from a patient dose. Indication is not a patient diagnosis.

`EvidenceEnrollmentService` reuses existing same-user repositories and immutable `source_documents.extraction_evidence`, `medication_source_links`, `medication_evidence_tasks`, private images and historical regimens. No migration is needed: new source evidence is stored in existing bounded JSON. Only an explicitly patient-supplied pharmacy-label/prescription source may propose personal instructions; provider `package/none` cannot authorize a plan. `label_kind=dispensing` is not source authentication.

The owned current medication list (up to20 names, opaque medication ids and known strengths, no patient identity) can be passed in the multipart comparison field. `list_check` remains advisory: no automatic linking/merging/activation. Task id restores across refresh. Name aliases exclude documented strength/release markers only when product metadata is independently compared. Different strength/form/release/ingredients/product code or incompatible explicit instruction parts persist a conflict. Both original sources remain available; existing active plans are not overwritten.

Parsed fixed dose/unit and food can prefill patient review. Dose ranges need clarification. Daily count/time-of-day wording never invent clock times. PRN never manufactures scheduled occurrences. Duration without an explicit start does not establish a full course. Supply quantity, dispensing date and expiry never establish dose/course. Daily count must match the patient's explicitly reviewed clock slots; contradictory dose/food/PRN cannot be silently activated. Interval instructions are retained/displayed, but this review screen does not activate interval plans. Patient review and separate activation confirmation remain mandatory. Intake remains the independent B14 challenge/confirm/atomic-write lifecycle.

Gemini keeps the same provider, tool loop and allowlist. `reconcile_medication_sources` receives owned verified task references, untrusted printed parts, missing fields/conflicts and a reviewable proposal. It cannot write a regimen or resolve conflicts. Patient summaries remain grounded in deterministic tool results. No model-supplied owner id or arbitrary tool from Stage2 is executed.

## Routing and personal gallery

`POST /api/sources/check-input` is authenticated, bounded and consented. It calls the typed routing port and projects a patient workflow suggestion. Provider `next_tools` is not executed. Request image types differ from response types (`printed`, `unchecked` are response-only); unclear/blister input asks the patient. Explicit enrollment/current-dose/unknown-pill intent remains primary. PDF is never sent to a pill endpoint.

Loose-pill embed requests enable `read_imprint`; match sends reads only when `text_reading=used`, and persists optional imprint outcome evidence. Unavailable/skipped/not_requested are not an imprint check. Matching stays stateless in Stage2; private reference eligibility, ownership and current/historical regimen reconciliation stay in PharmaScan. The optional adapter method `search_by_embedding` validates existing metadata and supports explicit catalogue lookup without re-embedding; automatic unknown-to-catalogue fallback is not enabled. Catalogue candidates are not a confirmed Singapore product identity or safe-to-take result.

## Live model limitations observed

Two initial generated-image OCR probes returned schema-valid results. The sticker returned dose1tablet, times_per_day2 and after_food. Separate `For 7 days. Swallow whole.` was retained as a caution, but structured duration was null. The model classified the initial strength-only box as dispensing; it missed the release marker on a separate line and selected a different RxNorm product than the ER sticker. Dispensing origin was not reliably read. These observations are not corrected by inventing values or discarding conflicts. The reproducible journeys use clearly printed single-line product/direction evidence and still require review.

PDF is supported by the upstream contract, but the application currently accepts bounded PNG/JPEG only. Text PDF and scanned PDF are **NOT VERIFIED / PARTIAL**, rejected clearly before inference; no generic PDF ingestion claim follows from OpenAPI. Whole-blister matching remains unavailable. Printed daily maximum is retained for human review, not converted into a validated automated clinical dose checker.

## Safety services and licensing

One REAL LIVE `/v1/safety/medications` synthetic probe returned200 and a valid coverage schema:2 medicines,1 screened,1 not screened,0 pairs checked,1 not checkable. It also returned all_identified=true while mapping the deliberately unknown input to an ingredient. Consequently these services are **not enabled in the patient runtime**. No empty-alert safety claim or independent dose/medication instruction follows. `/safety/dose` and `/safety/label` are not enabled or claimed live verified.

Service sources name DDInter2.0 / CC BY-NC-SA4.0. The [official DDInter terms](https://ddinter2.scbdd.com/terms/) explicitly restrict reuse to the noncommercial licence and warn about incomplete coverage; commercial medical-product permission is unresolved. [openFDA drug labeling](https://open.fda.gov/apis/drug/label/) is US submitted label data, not Singapore instructions or a personal prescription. No interaction checker or commercial clinical certification is claimed. Feedback/training endpoints are never invoked; private-gallery consent does not authorize external dataset sharing.
